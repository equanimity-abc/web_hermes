# 漫剧智能体健康检查报告与改进计划（R0–R8 完成后）

> 结论先行：R 系列把「统一配置 / provider 插件化 / 重试 / 一致性 / 批量 / 回滚 / 成本 / 验收」的**骨架、接口、UI 占位**都搭起来了，工作台可用、后台队列可用、锁/脏层可用。但存在 **3 个「配置路由与真实生成脱节」的核心缺口、2 个真实 bug、以及若干一致性与鲁棒性局限**。按本计划先修道 P0，再补 P1/P2，可逼近「专业顶级」验收标准。

---

## 一、总评

| 维度 | R 系列自评 | 实际核查 |
|------|-----------|----------|
| 三层配置覆盖 | 三层（全局 preset → 项目 models.json → 分集/单镜 overrides） | **只实现了两层**；第三层 `doc.overrides` 无读取/合并逻辑 |
| provider 插件化 | 动态加载，加模型不改业务 | adapter 加载与 dispatch 已通，但 **image/lip 生成未走路由表** |
| 生成鲁棒性 | 重试 + 熔断 + 降级清单 | 只有固定 0.5s 顺序重试，**无熔断**；降级清单存在但有漏洞 |
| 一致性硬闸 | 参考图 + identity ≥0.65 标脏可重抽 | 有 ArcFace，但**缺依赖时回退直方图余弦仍可「假通过」** |
| 批量/回滚/成本/验收 | 已交付 | 功能在位；成本闸接入口**不全**（见问题 9） |

**一句话**：功能闭环可跑通，但「配置中心决定一切」这条 R 系列主线在生产路径上没有完全穿透（尤其出图/口型/剧本三个节点），且 I2V 存在会误导用户的真 bug。

## 二、问题清单（分级）

### P0 —— 致命 / 必须修（阻断「专业顶级」与「不误导」）

#### 1. scene 出图不消费 `image` 路由表（R0/Q8 核心验收未真正达成）
- 位置：`backend/tools/drama_video.py` `_generate_scene_image()`（读 `config.IMAGE_GEN_PROVIDER`）；`drama_styles.image_route/estimate_image` 只用于**估费与提示词**。
- 现象：用户在工作台把 `image.dialogue.provider/model` 改成 `jimeng/char-consistent`，估费数字会变、提示词会加 LoRA 字样，但真实出图仍走全局 `IMAGE_GEN_PROVIDER=pollinations`。R0「节点配置落盘并生效」在 scene 节点**未生效**。
- 建议：`_generate_scene_image` 收 `slug`/`shot`，内部调 `drama_styles.image_route(slug, shot)` 取 `provider`，走 `registry.dispatch("image", ...)`；`refs` 已有，补上 `model/lora/cost_per_shot` 语义（真 adapter 接真模型，txt2img 兜底提示词）。

#### 2. 口型生成不消费 `lip` 路由表（估费与生成脱节）
- 位置：`backend/tools/drama_lip.py` `try_generate_lip()` 用 `_provider()`（读 `config.LIP_PROVIDER` env），而 `estimate_lip()` 用 `resolve_provider(models, lip.provider)`。
- 现象：改 `lip.provider=musetalk`，估费变了、`estimate_lip` 显示走了口型，实际生成仍按 env 的 `mock`。建议显式传 `models`/`provider` 进 `try_generate_lip`，与 `estimate_lip` 一致地 `resolve_provider`。

#### 3. I2V `retry_call` 返回值被误判布尔 → 失败不回退、误报成功
- 位置：`backend/tools/drama_i2v.py` `try_generate_i2v()`：

  ```python
  ok = retry_call(registry.dispatch, "i2v", provider, ..., ok=lambda r: r == "ai")
  if not ok and provider not in (...):          # ← ok 是字符串 "ai"/"none"，恒真
      ok = bool(...)
  ...
  if ok:            # ← "none" 也是真值
      return "ai"   # ← provider 失败仍返回 ai
  ```

- 影响：`registry.dispatch` 失败返回 sentinel `"none"`，`retry_call` 把**最后一次结果原样返回**（字符串），`if ok` 恒真 → 所有 I2V 失败都不会走 Ken Burns 回退，且对上层标记 `i2v_source="ai"`，但 `motion` 文件可能不存在/为空。这是**会直接误导验收的 bug**。
- 建议：`ok = retry_call(...); ok = (ok == "ai")`，或把 dispatch 包一层返回 bool；`_provider_l3_mock`/`compose_keys_motion` 的 bool 语义统一。

#### 4. L3 真 I2V 恒被本地 mock 短路（Q3「action 默认真 I2V」未落地）
- 位置：`drama_i2v.try_generate_i2v()`，`if planned == "L3": ok = _provider_l3_mock(...)`。
- 现象：即使路由把 action 镜的 provider 解析为可用的 `kling`（`estimate_i2v` 返回 provider=kling），实际仍跑本地双段 Ken Burns `_provider_l3_mock`，真 `_provider_http`/adapter 从不执行。pro 档切了 L3 却不产真 I2V。
- 建议：L3 先按 `provider=resolve_provider(...)` 走 adapter（http/kling/hailuo），失败再回落 `_provider_l3_mock` 降级并记录 `degraded`。

#### 5. 「三层覆盖」第三层（分集/单镜 overrides）未实现
- 位置：`drama_config.put_node_config()` 写的是项目级 `models.json`；`drama_styles.effective_models()` 只叠加 style，**未读分集 doc 里的 `overrides`**。
- 现象：ROADMAP 说「③ doc.overrides（工作台检查器可改），读配置按 ③>②>①」，但代码里 `overrides` 既无落盘也无合并。实际只有「全局 preset → 项目 models.json」两层。
- 建议：定义 `{slug}/videos/epNN/shots.json` 内 `models_overrides`（或 `doc.overrides`）schema，`effective_models` 增加第三层合并；`put_node_config` 支持 `scope=episode/shot`。

### P1 —— 高优（逼近专业水准）

#### 6. 「熔断」缺失，只有顺序重试
- 位置：`backend/tools/drama_retry.py` 只有 `retry_call`（3 次、固定 0.5s、无退避、无熔断、无降级清单装配）。
- 建议：补 `CircuitBreaker(provider_id)`（失败阈值/冷却/半开）与指数退避；失败把结构化原因（provider、attempts、error type）写进 shot 的 `degrades`，而非只有文案。

#### 7. identity / lip 可「假通过」：proxy 直方图余弦被当成有效分数
- 位置：`backend/tools/drama_qc.py` `score_pair()` 缺 ArcFace 时回退 `_hist_embedding`（64 bin 直方图），且 `status="ok"`；`qc_passed()` 只看 `status=="ok" and pass`。
- 影响：无 insightface 的环境下，锁参考图与本镜的**直方图余弦 ≥0.65 就判通过**，但直方图余弦在 0.65 阈值下无物理意义，可能「假通过」。违背「skipped 不得记为通过」原则。
- 建议：`method=="proxy"` 时 `status` 标 `degraded`（或 `required` 不通过 + 明确提示「缺 ArcFace，无法判定身份」），在 `qc_passed`/验收页降级显示；只有 `arcface` 方法才能 `ok+pass`。

#### 8. ArcFace 每次抽检重建模型，性能差
- 位置：`drama_qc.py` `_arcface_embedding()` 每张图 `FaceAnalysis(name=...).prepare()`。
- 建议：模块级缓存单例 `app`（首次构建 + `prepare`），避免逐镜冷启动。

#### 9. 预算闸「只估不实、覆盖面不全」
- 位置：`drama_models.budget_state()` 的 `spent` 是 `estimate_*` 估算值，无「实际已消费」落账；`_assert_budget` 只在 `generate_i2v_shot/generate_lip_shot/generate_keys_shot` 三处调用。
- 影响：`render_episode`（整集重渲，比例最大）、`generate_candidates`（出图）不受预算约束，超支无法阻断；且「已花」永远等于「估计」。
- 建议：成功生成时把 `provider + cost_per_shot` 追加到 episode `cost_log`，`_assert_budget` 在 render/draft 入口也挂上；`budget_state` 的 `spent` 优先读 `cost_log` 实际值。

#### 10. 单镜重渲丢降级可见性
- 位置：`drama_video.rerender_shot()` → `render_shot_layers()` 返回 `degrades` 后，`rerender_shot` 未把 `degraded` 清单回填 `_episode_result`。
- 建议：`rerender_shot` 把本镜 `degrades` 写进 shot 与返回 payload（对齐 `render_episode_video` 的 `degraded`）。

### P2 —— 中优 / 长期

#### 11. `script` 节点配置未接线（剧本草稿→精修不生效）
- `llm_client.py` 固定 `config.DEEPSEEK_MODEL`，`script.provider/model/refine_model` 躺在 models.json 无人消费。剧本生成的「flash 草稿 + reasoner 精修」未真正按节点配置执行。

#### 12. 无测试目录
- 关键不变量（retry 语义、路由 fallback、快照恢复、预算闸、锁/脏层）应补 `backend/tests/`；当前无任何断言守护，后续改动极易回退（本次发现的 P0-3 正是典型）。

#### 13. 大单体 + 薄封装重复
- `drama_studio.py`(1588) / `tiktok_drama.py`(1179) / `drama_video.py`(1449) / `drama_qc.py`(990) / `drama_models.py`(629) 偏大；`tiktok_drama._action_*` 大量是再转调 `drama_studio` 的薄封装。可抽公共参数解析与错误的统一映射，减少双份维护。

#### 14. LLM 用量无成本治理
- R7 的成本治理只覆盖漫剧「出图/运动/口型」，不覆盖 Agent loop 的 LLM token/调用量。补齐 `usage` 计量后才能在通用腰上闭环成本。

#### 15. `render_shot_layers` 里 `_path_for` 未捕获 `resolve_safe` 的 `ValueError`
- assets 缺失/非法路径时抛 500，而非业务错误。应先校验 assets 存在，给出可读提示。

## 三、改进计划（排期）

### 第 1 轮：修道 P0（约 3–5 天，完成后才谈「专业顶级」）
1. 修 `drama_i2v.try_generate_i2v` 的 `ok` 布尔误判 + L3 先真后 mock 降级（问题 3、4）。
2. `_generate_scene_image` 走 `image_route`（问题 1）；`try_generate_lip` 走 `lip` 路由（问题 2）。
3. 实现第三层 `overrides` 合并（问题 5）：定义 schema + `effective_models` 合并 + `put_node_config(scope=episode/shot)`。
- **验收**：工作台给某镜换 image/lip provider 后，真实生成调用对应 adapter；I2V 失败能回退 Ken Burns 且 `i2v_source` 诚实；L3 在 kling 可用时真走 http。

### 第 2 轮：补 P1（约 1–2 周）
4. 熔断 + 指数退避 + 结构化降级清单（问题 6）。
5. proxy 分数降级为 `degraded`，禁止 proxy 直接通过；缓存 ArcFace 单例（问题 7、8）。
6. 预算闸扩到 render/candidates，并落 `cost_log` 实际消费（问题 9）。
7. 单镜 rerender 回填 degraded 清单（问题 10）。
- **验收**：一集渲染后「成功/失败/降级」齐全且可审计；无 insightface 时身份项为「未判定」而非「通过」；预算超支时整集与出图均被阻断。

### 第 3 轮：P2（按需）
8. `script` 节点接线 + LLM 用量计量（问题 11、14）。
9. 抽公共解析/统一错误映射（问题 13）。
10. 建立 `backend/tests/` 守护核心不变量（问题 12）。
- **验收**：`pytest` 覆盖 retry/路由/快照/预算/锁；剧本精修按节点配置生效；成本面板同时显示 LLM 与生成用量。
